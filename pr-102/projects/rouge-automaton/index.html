Rouge Automaton

Go Discord RAG bot with a 10-round tool loop, exact-match Mongo intel tools, live war status + Major Orders, catalog + wiki sync, and a roleplayed defector persona.

Architecture

Key decisions

Tools over a vector store
Retrieval is exact-match Mongo lookups over collated indexes with aliases, not embeddings. Nine tools cover units, gear, places, war status, major orders and wiki search — nothing to re-embed when the wiki edits a page.
One tool definition, two consumers
The same Execute implementation backs the Discord bot's tool loop and the stdio MCP server, so a new capability lands in both places at once and the bot's behaviour can be tested without Discord.
Failure is voiced, never silent
A 429, a dead relay or an exhausted quota each has an in-character reply with an ETA, and replies are capped at 1900 runes so the sign-off always lands inside Discord's 2000-rune ceiling.

The problem

Game wikis are huge, slow to search mid-session, and go stale. The idea: a Discord bot that answers Helldivers 2 intel questions (units, counters, loadouts, biomes, live war status) from a local cache that refreshes itself — with a personality players actually enjoy talking to.

What I built

A Go-only bot (no Python runtime) roleplaying a defected informant. Questions flow through a think-act loop of up to 10 tool rounds over exact-match Mongo intel tools — unit/gear/world lookups, generic war summary, Major Order briefing (title, kill/objective progress, expiry, reward, plus companion strategic-threat tasks), named-planet status, wiki search — defined once and shared between the relay client and an MCP stdio server. The relay is OpenCode Go (muse-spark-1.3-contributor), one provider with no fallback chain. Retrieval is Mongo exact-match with cited context (collated indexes, alias handling); on a local miss it falls back to live wiki lookup with source links. Live war status comes from the Training Manual API with a staleness guard, answering generic “how goes the war” questions without needing a planet name. Gear shelves sync daily from a public catalog snapshot (ETag-conditional, cached in Mongo); units and world are crawled politely from the wiki, and a self-feeding watcher polls the wiki RecentChanges feed every 5 minutes, routes unseen pages to a shelf, and re-parses only changed pages.

The craft is in the guardrails: allowlist + mention gating with auto-threads, model replies bounded at 1900 runes with an in-voice “cut short” trailer so the sign-off lands inside Discord’s 2000-rune ceiling, the persona compiled into the binary with serial numbers redacted and every transmission ending in Over., and unreleased gear met with a requisition refusal instead of guessed handling. Failure is voiced in character — a 429 gets a “busy spreading democracy” reply with a liberation ETA, never silence. Client-side token-bucket rate limiting backs that up, with /status (health + relay probe) and /cooldown (quota inquiry) ops commands and a typing indicator while the model works. Services ship as static binaries in a distroless image under Podman Compose (bot, watcher, catalog sync, crawl), alongside Mongo, seeded by a one-shot ingest from checked-in intel data covering units, gear, and world shelves.

What it taught me

Constraints make bots: capped tool rounds, clamped result counts, and canned failure modes turn an LLM integration from a demo into something that behaves in production. And embedding the persona at compile time means the character survives every redeploy bit-for-bit.
