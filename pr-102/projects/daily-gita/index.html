Daily Gita

Offline-first verse reader: a trilingual SQLite corpus (701 scraped rows) bundled as an app asset, no backend.

React NativeExpoexpo-sqliteNativewindScrapy
GitHub ↗

Architecture

Key decisions

Ship the corpus, not an API
The whole Gita is a 2.8 MB SQLite file bundled as an asset, opened by SQLiteProvider on first launch. No accounts, no backend, no sync conflict to resolve — the app works in a metro tunnel.
Scrape once, per language
One Scrapy spider per language writes a trilingual CSV, and the database is built from that file. Re-scraping is a batch job, not an app release.
History is meant to stay on the device
The schema has a local history table so a reading log never needs a server, but nothing writes to it yet — the design keeps reads local, not the feature shipped.

The problem

Devotional apps shouldn’t need accounts, backends, or connectivity. A daily verse reader is the perfect offline-first app: the entire corpus fits in a few megabytes, so ship the database with the app and never phone home.

What exists (in development)

Scrapy spiders crawl English, Hindi, and Telugu verse pages into a trilingual CSV, compiled into a SQLite database (701 rows) bundled as a 2.8 MB app asset and read through SQLiteProvider — zero network calls. Around it: a drawer shell via expo-router, Settings, Terms and Privacy screens.

Honest status

UI prototype. The dataset and bundling are done; the reading loop is not. The home screen renders placeholder text, getVerse() ignores its arguments and returns the first row, the language picker is useState that is never persisted, and the history table has no writer. The scraped data also needs a cleanup pass: 701 rows contain only ~590 distinct chapter/verse pairs, so duplicates are still in the bundle.

The data pipeline was the hard part and it’s finished — the app around it is what’s left.
