Schedio

Three-sided collaboration platform with GridFS uploads, per-file AI explanations, and plagiarism checks.

ReactNode.jsExpressGemini APIMongoDBDocker
GitHub ↗Live demo ↗

Architecture

Key decisions

Three role tiers, one codebase
T1 students, T2 colleges and T3 recruiters each get a scoped view — colleges only see their own students' projects, recruiters see everything — behind one React app and one Express API.
Big files in GridFS, metadata in MongoDB
Project ZIPs, video and photos are stored in GridFS while documents keep only metadata, so uploads never ride inside a document and the queries stay small.
Checking happens where the upload happens
Gemini explains uploaded code file-by-file and a plagiarism API scores submissions in the same flow, so a project is reviewed before it ever appears in a feed.
Sessions, not JWTs, for the app
All three roles live on one MongoDB-backed session with a 6-hour rolling cookie; JWT is used only for the 10-minute password-reset link, where a bearer token is the right shape.

The problem

Student projects are scattered across GitHub profiles nobody finds, and recruiters have no good way to discover them through colleges. I wanted one place where students, colleges, and recruiters meet around real work — with the evaluation tooling recruiters actually need.

What I built

Schedio serves three roles from one codebase: students upload and showcase projects, colleges manage their students’ work with monthly analytics, and recruiters search across everything with institute and domain filters. Auth is email + bcrypt with Mongo-backed sessions (JWT only for the 10-minute password-reset links), and role checks gate the student, college and recruiter views.

The core loop is upload → explore → evaluate. Projects bundle code ZIPs, videos, and images into GridFS; the backend unzips code server-side and serves a file-tree viewer where each file gets its own gemini-2.5-flash explanation. Project descriptions are scored by a RapidAPI plagiarism service before submission, and engagement (likes, comments, recruiter bookmarks) is first-class. Colleges get Chart.js monthly analytics; profiles are print-friendly for handouts. Password reset flows through Gmail templates, and the whole thing ships in Docker (dev + prod Dockerfiles) with the live deployment on Vercel.

What it taught me

Marketplaces die of emptiness, not bad UI — so the evaluation tooling (plagiarism checks, per-file code explanations, analytics) is what makes the platform useful to recruiters rather than just a prettier project list. And boring auth choices (sessions in Mongo, short-lived reset tokens) pay off when three user types share one API.

Where it stops

It was built for a hackathon and it shows in the edges: search uses Mongo $text but no text index is created in the repo, so it depends on indexes made by hand; the plagiarism verdict is computed from state one render behind (ProjectUploadForm.jsx:236-251 reads percent captured before the request), so a clean description can be flagged and a flagged one can slip through; and there are no tests. The three-role flows are the part that works.
