LeetCode Scoreboard

Group LeetCode board scored by acceptance rate, synced every five minutes.

2026 · Solo

Next.js · TypeScript · MongoDB · Mongoose · Web Push · ECharts

Source ↗

The problem

Counting solved problems rewards grinding easies, and hitting LeetCode on every page view is slow.

How it works

Each accepted problem scores 100 − acceptance rate, pinned the first time it is accepted. An external cron hits /api/sync every five minutes, walks tracked users through recentSubmissionList, and upserts one document per user and question. The dashboard only ever reads Mongo aggregations — it never calls LeetCode — so the board renders when LeetCode is slow. New solves trigger a Web Push summary.

The progress chart is cumulative per user per day in IST, over 1D to ALL ranges, fed by a dedicated /api/history read on the same pre-aggregated data.

A CORS-enabled GET /api/public/stats?username=<handle> endpoint proxies live solved counts plus contest rating/ranking for this portfolio site, with 1h in-memory/CDN caching, per-IP rate limiting, and an optional username allowlist.

Impact

Four tracked users, 373 problems scored for 11,529.58 points across 66 active days in the 81-day season (2026-09-08 to 2026-11-27), measured from GET /api/overall on 2026-11-28. 100% clean sync runs on the five-minute cron to date, per Vercel function logs and owner monitoring; the app keeps no per-run log. Push delivery works end to end but is unmeasured.

Scope

Syncs every five minutes; the dashboard only ever reads pre-aggregated Mongo data, so the board stays fast when LeetCode is slow.
