Rouge Automaton

Discord bot answering Helldivers 2 questions from a Mongo cache it refreshes itself.

Go · discordgo · MongoDB · Podman Compose

Source ↗

The problem

Game wikis are slow to search mid-session and go stale, so answers need a local cache.

How it works

Go-only, no Python. Questions go through a think-act loop of up to 10 tool rounds over exact-match Mongo lookups — units, gear, planets, war summary, Major Orders — with the same tool definitions shared between the Discord client and a stdio MCP server. The relay is a single OpenCode Go model, no fallback chain.

Gear syncs daily from a public catalog snapshot, units and world are crawled from the wiki, and a watcher polls RecentChanges every five minutes and re-parses only changed pages. On a local miss the bot falls back to live wiki lookup with source links. Live war status comes from the Training Manual API.

Guardrails: allowlist and mention gating, replies capped at 1900 runes so the sign-off fits Discord’s 2000-rune ceiling, in-character failure replies with an ETA instead of silence, and rate limiting client-side. Ships as static binaries in a distroless image under Podman Compose.

Limits

Exact match, not search: misspelled planet names miss the cache and cost a live lookup. One model provider means a dead relay is a dead bot, voiced in character but still dead.
